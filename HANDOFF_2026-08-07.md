## 2. Things that will look like bugs but are not

Check here before "fixing" any of these.

### Change password does not ask for the current password
Deliberate, decided 7 Aug. `ProfessionalPasswordChangeSerializer` has **never**
declared `current_password`; mobile used to send it and DRF silently discarded
it, so the field was never a real check. It also cannot work for Google
accounts, which have no password to re-enter. Full reasoning and the accepted
residual risk are in `Backend_TODO_From_Parity_Review.md` §C.

### Four API methods are uncalled
`getProgress`, `getClientMeetings`, `getClientPaymentUnread`, `deleteAccount`.
Left in place on purpose — each may be an intended feature rather than dead
code. Listed for a product decision; do not delete without one.

### Google sign-in hides itself
The button only renders when `Env.googleServerClientId` is non-empty, which
comes from a **build flag**. If it is invisible, the build lacked
`--dart-define-from-file=dart_defines.json`. Not a code fault.

### `google_button_web.dart` looks orphaned
It is reached through a conditional export in `google_button_platform.dart`
(`if (dart.library.js_interop)`). Static scans miss this. Do not delete.

### `AppTokensX` / `LegalAudienceX` look unused
Dart extensions — used implicitly (`context.tokens`), so the type name never
appears at a call site.

## 3. Local config you need to build

`mobile_flutter/dart_defines.json` is **git-ignored** and will not exist on a
fresh clone. Copy `dart_defines.example.json` and fill it in:

```json
{
  "API_BASE_URL": "https://192.168.4.68",
  "GOOGLE_SERVER_CLIENT_ID": "<value of GOOGLE_OAUTH_CLIENT_ID from backend/.env>"
}
```

Run with:

```
flutter run -d web-server --release --web-hostname 127.0.0.1 --web-port 8080 --dart-define-from-file=dart_defines.json
```

The client ID must match the backend's byte for byte — the backend verifies the
ID token's `aud` claim against it.

## 4. Open items

### Blocking Google sign-in (user action, not code)
Google Cloud Console → Credentials → OAuth web client → **Authorized JavaScript
origins** must include the origin the browser actually loads from
(`https://192.168.4.68`, not `127.0.0.1:8080`). GIS reports rejections only in
the browser console.

## 6. Working agreements established this week

- **Never edit `backend/`.** Backend needs go in
  `Backend_TODO_From_Parity_Review.md` instead.
- **Web and mobile share business logic, data, terminology, colours,
  visibility rules and settings.** Only navigation and layout may differ.
- **Editing never happens inline.** An explicit edit button opens a dialog or a
  dedicated screen with its own Save/Cancel.
- **Explanations live behind `i` icons**, not as permanent paragraphs. Screens
  carry actions and data.
- Verify with `flutter analyze` after every batch. A brace-balance script is
  not enough — it once passed a file where a class header had been spliced out
  and its `build` method absorbed into the wrong class.
